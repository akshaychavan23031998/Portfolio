# Selected Work technologies and case-study audit

Audit date: 7 August 2026

## Architecture findings

| Area                | Current implementation                                                                                                                                                       | Finding                                                                                                                                                         | Planned change                                                                                                               |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Homepage cards      | The reference HTML body is extracted in `src/app/page.tsx`, then images and newer cards are injected into the string.                                                        | Rabbit and the original eight cards use reference markup; Three-Way Match Engine and Pipeline Builder use `referenceProjectCard()`.                             | Apply one ordered, data-driven post-processing pass to all 11 card fragments.                                                |
| React project grid  | `src/components/project-grid.tsx` renders a separate typed React grid.                                                                                                       | It conditionally hides tags with `showTechnologiesOnCard` and links eligible projects to routes.                                                                | Keep it consistent with the homepage: chips and modal-trigger buttons for every project.                                     |
| Technology chips    | Reference cards use `.pills > .pill`; the React grid uses `.tags > span`.                                                                                                    | Rabbit, Three-Way Match Engine, and Pipeline Builder currently opt out through `showTechnologiesOnCard: false`. Most original reference cards have no chip row. | Use one `cardTechnologies` subset (maximum six) while preserving the complete `technologies` arrays.                         |
| Rabbit modal        | Static `#caseModal` markup lives in the reference HTML. `public/reference-runtime.js` assigns the same open handler to every `.case` button but never changes modal content. | Rabbit works because it is the only current homepage `.case` trigger and the modal contains fixed Rabbit copy.                                                  | Replace the fixed runtime behavior with one React modal driven by the selected project slug.                                 |
| Modal accessibility | The legacy modal supports close, backdrop click, and Escape.                                                                                                                 | It does not provide a complete focus trap, focus restoration, background isolation, or data-driven title/content.                                               | Add one reusable dialog component with focus management, scroll lock, Escape/backdrop/close handling, and optional sections. |
| Project actions     | Reference cards contain Code and Live/Demo anchors. `ProjectGrid` adds route-based Case study links unless `hasCaseStudy` is false.                                          | Case-study behavior differs between Rabbit, routed projects, and the two route-disabled projects.                                                               | Render Case study as a button for all cards; preserve every existing external URL and Live/Demo label.                       |
| Routes              | `caseStudyProjects` excludes only projects with `hasCaseStudy: false`. Dynamic pages and sitemap use that list.                                                              | Three-Way Match Engine and Pipeline Builder are correctly excluded; other direct routes remain generated.                                                       | Do not remove route infrastructure or change eligibility. Cards will no longer link to routes.                               |
| History             | Existing route links create navigation entries; Rabbit's modal does not.                                                                                                     | Behavior is inconsistent.                                                                                                                                       | Modal triggers will not call router APIs or mutate the URL.                                                                  |
| Card layout         | `.project` is a flex column and `.project-meta` uses `margin-top: auto`.                                                                                                     | Chip rows can occupy the space above the action row without changing global card dimensions.                                                                    | Insert chips between media and metadata and keep action alignment through the existing flex flow.                            |

## Files expected to change

- `src/data/projects.ts`: presentation subsets and optional case-study data.
- `src/app/page.tsx`: data-driven chip and modal-trigger injection; remove the legacy fixed modal from rendered output.
- `src/components/project-case-study-modal.tsx`: one reusable accessible modal.
- `src/components/project-grid.tsx`: consistent chip and modal-trigger presentation.
- `src/app/reference.css`: focused modal/card-chip layout rules.
- `public/reference-runtime.js`: remove the obsolete fixed-modal handlers only.
- Focused project unit and E2E tests.

The reference HTML remains the untouched source file. No project route, sitemap, filter, scrolling, theme, navigation, contact, or EmailJS behavior is planned for modification.
